Purpose and intended users

The project brief describes a local Windows tool for Adcut that converts customer logos into 2D CAD drawings for water jet cutting. Different logo colors represent different flooring or turf materials, so color boundaries must become separate closed vector paths. Intended users identified in the brief are Adcut operators and CNC programmers.

Initial functional requirements

The following are drawn from the project brief and remain subject to client validation:

  • Accept JPEG, PNG, WEBP, GIF, and PDF input.
  • Provide configurable color reduction to separate material regions.
  • Trace color boundaries into closed vector paths without gaps or overlaps.
  • Allow review and adjustment before export.
  • Export SVG and R12/R2000 DXF files.

Proposed workflow: upload image → color reduction → vectorization → review and tweak → SVG/DXF export.

Initial non-functional requirements

  • Run locally on Windows.
  • Use an open-source, commercially viable stack.
  • Provide an intuitive interface for operators.

Supported Windows versions, hardware requirements, processing-time targets, accuracy tolerances, and measurable usability criteria have not been confirmed.

Draft user stories

These are team interpretations of the project brief, not statements collected from a client interview.

  • As an Adcut operator, I want to import customer artwork so that I can prepare it for CAD conversion.
  • As an Adcut operator, I want to reduce colors into material regions so that each region can be represented by closed paths.
  • As an Adcut operator, I want to review and adjust the traced result before exporting it.
  • As a CNC programmer, I want SVG or DXF output that can be used in the downstream cutting workflow.

Story priorities and acceptance criteria are pending client input.

Interfaces and implementation options

The brief proposes Streamlit or React/Vue for the interface, OpenCV for image processing, Potrace/vtracer for tracing, ezdxf for CAD export, and Docker/PyInstaller for development or packaging. These are candidate technologies, not final design decisions.

The downstream CAD/CAM software, required DXF entities, units and scale, layer conventions, and installation approach are not yet confirmed. No screen layout or detailed interface behavior has been approved.

Open questions for client validation

The following identify gaps in this draft. They are not a verbatim copy of the questions already emailed to the client.

  • What is the current logo-to-CAD workflow, and which steps cause the most difficulty?
  • Which input and export formats are essential for the first version?
  • What sample logos and corresponding acceptable CAD outputs can be used for validation?
  • How should colors map to materials, and which adjustments must operators be able to make?
  • What geometric tolerances, minimum feature sizes, units, and scaling rules are required?
  • Which CAD/CAM tools must accept the exported files?
  • Which Windows versions and hardware must be supported?
  • What processing times, usability expectations, and acceptance tests define success?
  • What features are priorities, and what is outside the agreed project scope?

No numerical thresholds, performance promises, or final scope commitments are set in this draft.
