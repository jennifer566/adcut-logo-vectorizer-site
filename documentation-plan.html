Writing and accessibility standards

  • Put the required action first and use the same labels shown in the application.
  • Define CAD and vector terms on first use; avoid assuming programming knowledge.
  • Use numbered procedures with expected results and recovery steps.
  • Provide text alternatives for diagrams and captions or transcripts for videos.
  • State known limitations beside affected tasks, especially before DXF download or cutting.
  • Keep source documentation versioned with code and update screenshots after interface changes.

Production schedule and ownership

  • October 26: publish this plan and the initial user manual.
  • By November 9: add tested Windows installation steps and updated screenshots.
  • By November 16: review terminology and procedures with a teammate who did not write them.
  • Before acceptance testing: add confirmed AutoCAD/IGEMS versions and client workflow checks.
  • Before handoff: record and caption the install/start and convert/export videos; verify every link from a client-controlled account.

Team E collectively maintains the public documentation. The technical reviewer verifies architecture and developer instructions; the client-contact role verifies that operator and handoff instructions match the agreed workflow. Every team member reviews the final documentation.

Completion criteria

Documentation is complete when a new operator can install or receive the application, process a permitted sample, understand warnings, export files, and find help without developer intervention; a future developer can run tests and trace data flow; and the client can retain all documentation and videos in an environment they control.
