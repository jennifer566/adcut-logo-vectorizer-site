Client Handoff Plan

Status: Team plan updated October 26, 2026. Client-controlled destination accounts, workstation access, CAD versions, final appointment, and acceptance criteria remain unconfirmed.

Handoff outcome

Adcut should finish the semester with a working local application, source and release materials it controls, repeatable installation and recovery instructions, operator and developer documentation, test evidence, and a clear list of limitations. A GitHub link by itself is not a complete handoff.

Step-by-step handoff

  1. Confirm the client owner, target Windows workstation, supported AutoCAD/IGEMS versions, repository destination, and final handoff appointment.
  2. Freeze the accepted requirements and identify features or tests that remain incomplete.
  3. Create a release candidate from a reviewed commit and rerun the full automated matrix.
  4. Test installation, start, conversion, SVG/DXF download, restart, update, and uninstall on a clean Windows machine.
  5. Run client-approved CAD import and physical validation; record results without marking unavailable tests as passed.
  6. Copy or transfer code, releases, samples, documentation, videos, and issue history to client-controlled storage.
  7. Conduct a walkthrough: install, process a sample, interpret warnings, verify scale and paths, report a defect, recover from failure, and obtain updates.
  8. Have the client representative repeat the workflow and record accepted items, rejected items, deferred work, and owners.
  9. Verify access after the meeting and provide the final release identifier and checksums.

Accounts, ownership, cost, and dependencies

  • The application stack is open source, but every dependency license and release version will be included in the final inventory.
  • GitHub, video, and file-storage ownership must be transferred or copied to accounts controlled by Adcut.
  • Any signing certificate, installer service, cloud storage, or paid CAD dependency must have its owner, recurring cost, renewal date, and cancellation path recorded. No such paid service is currently confirmed.
  • Customer artwork remains local unless the client explicitly approves another storage path.
  • Student credentials and personal access tokens will not be included in the delivery.

Acceptance checklist

  • Client can access every deliverable without relying on a team member's private account.
  • Application installs or starts from the documented source workflow on the agreed workstation.
  • A permitted sample completes upload, vectorization, review, and export.
  • Client confirms scale, units, layers, topology, curve behavior, and downstream compatibility for agreed samples.
  • Known limitations and unresolved issues are understood and recorded.
  • Client knows how to back up, restore, update, and report a defect.
  • Final acceptance or requested corrections are documented after the handoff appointment.

Contingencies

If standalone packaging is not stable, deliver the locked uv installation with a tested startup script and explain the additional dependency. If CAD or cutting access is unavailable, deliver automated and visual evidence while labeling production validation as blocked. If repository transfer cannot be completed, provide a verified archive and written instructions, but keep transfer as an open action.
